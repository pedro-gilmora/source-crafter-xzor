# PWA Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. After each task's review, dispatch `.github/skills/subagent-driven-development/perf-memory-reviewer-prompt.md`; its blocking findings enter the fix loop like the task reviewer's.

**Goal:** An xzor app that has a `manifest.webmanifest` next to its `index.html` can be installed and keeps working offline after `xzor build`; apps without one build exactly as today.

**Architecture:** The web standard file is the configuration: no decorator, no new syntax. When `xzor build` (not `--watch`) finds `<project root>/manifest.webmanifest`, `src/bundle.ts` checks it, writes a dependency-free service worker to `<project root>/sw.js` (beside `index.html`, so its scope is the app's folder, sub-paths included) with a versioned precache list, and adds one registration line at the end of the bundle. `xzor dev` answers `/sw.js` with a worker that unregisters itself, so a production worker never serves stale code in development.

**Tech Stack:** Bun (`Bun.build` `footer`, `Bun.hash`), service worker APIs; no new dependencies.

**Spec:** [docs/plans/backlog-pwa.md](backlog-pwa.md), narrowed by these decisions (the user delegated them): configuration is the standard manifest file instead of `@Pwa(...)`; asset names stay unhashed (the worker's versioned cache handles updates); "update available" UI (backlog step 4) is out of scope; icons are required, not generated.

## Global Constraints

- No `manifest.webmanifest`: `dist/` output byte-identical to today, no `sw.js` written; a stale generated `sw.js` (first line `// Generated by xzor. Do not edit.`) is deleted. A user-written `sw.js` (other first line) is never touched.
- Never under `--watch` (so never in `xzor dev`): no `sw.js` written or deleted, no registration in the bundle.
- Registration line, appended to the entry bundle only: `if ("serviceWorker" in navigator) navigator.serviceWorker.register(new URL("<rel>/sw.js", import.meta.url));` where `<rel>` is the path from the bundle's directory to the project root, `/`-separated (`..` for `dist/`).
- Precache list (paths relative to the project root, `/`-separated, sorted, unique): `./`, `index.html`, `manifest.webmanifest`, every icon `src` in the manifest, every local `href`/`src` in `index.html` (no scheme, not starting with `//` or `#`, existing file), and every build output except `*.map`.
- Cache name `xzor-<version>`, version = hex `Bun.hash` over the precached files' contents in list order. Activation deletes other `xzor-` caches.
- Worker fetch: only same-origin GET; navigations network-first, falling back to the cached `index.html`; everything else cache-first, then network.
- Manifest check: warnings on stderr as `xzor: manifest.webmanifest: <problem>`, never failing the build: invalid JSON; missing `name` or `short_name`; no icon with `sizes` containing `192x192` and none with `512x512`; an icon file that doesn't exist; missing `display`. `start_url`/`scope` are left to the author (relative values work under any base path).
- Zero Rust crates; no new npm dependencies.

## Review Focus

- An app served under a sub-path (`<base href="/repo/">`, GitHub Pages): the worker registers with scope `/repo/` and offline deep links render.
- A rebuild with no change: same `sw.js` content (same version), so browsers don't reinstall.
- A manifest added, then removed: `sw.js` appears, then is deleted; `dist/` returns to byte-identical.
- `index.html` referencing remote assets (`https://...`) or anchors: not precached.
- A deploy that copies only some files (like `docs/site/publish.ts`): every precached path exists in the published folder.

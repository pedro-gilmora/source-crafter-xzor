# Application Bootstrap and Dependency Injection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compile-time dependency injection modeled on SourceCrafter.DependencyInjection: `@ServiceProvider`/`@Mount` classes plus `@inject` in `.tszor` become generated TypeScript providers and a generated `.zor/<entry>` bootstrap.

**Architecture:** A Bun script (`src/di.ts`) uses TypeScript 7's checker (`typescript/unstable/sync`) to extract facts as JSON. Rust (`src/di/`) parses the facts, resolves and validates the graph (ZDI01–ZDI08), and emits TypeScript into `.zor/`. `zor build` runs this after compiling components and before the type check. The bundle entry becomes `.zor/<entry>` when the entry declares `@Mount`.

**Tech Stack:** Rust 2024 (no crates), Bun 1.4, TypeScript 7 (`typescript/unstable/sync`), happy-dom.

**Spec:** [docs/superpowers/specs/2026-10-12-di-bootstrap-design.md](../superpowers/specs/2026-10-12-di-bootstrap-design.md)

## Global Constraints

- No new Rust dependencies. JSON goes through `src/json.rs` (`Json::parse`, `get`, `as_str`, `as_array`, `as_usize`).
- No locks. Caching is `??=`. Singletons are `static` fields of the generated class; scoped services are instance fields.
- Root `dispose()`: `#disposed` guard; singletons first (reverse creation order), then `#disposeScoped()`. Scope `dispose()`: only `#disposeScoped()`. Each disposer clears its field before releasing. Transients are never tracked.
- Transients without parameters get no member; they are inlined as `new Impl()`.
- Generated files live in `.zor/` and are never edited by hand. `.ts` sources are imported with real relative paths (`../../services/data`); components with `./X.tszor` relative to the `.zor` sibling.
- Getter name: the key, else the service type text camelCased without a leading `I` + uppercase letter (`IDatabase` gives `database`, `AuthService` gives `authService`). A collision gets `1`, `2`, ... appended in registration order.
- Async services (factory returns `Promise<T>`, or a dependency awaited by it is async, transitively) get a method `get<Name>Async(): Promise<T>` instead of a getter. It has two flat fields, `#<name>` (the value) and `#<name>$Promise`, both `static` for singletons; there are no holder objects. Parameters typed `Promise<T>` get the unawaited promise and do not propagate async-ness.
- Memory and performance first (repo premise): no allocation beyond what hand-written code needs. No `WeakMap`s, wrapper objects or extra closures in hot paths.
- Resolver shape: `if (this.#x$Promise) return this.#x$Promise;`. Then, if every awaited dependency's value field is `!== undefined`, it sets `this.#x$Promise = Promise.resolve((this.#x = new X(...)))`. Otherwise it sets `this.#x$Promise = this.#createX()`, where `async #createX()` starts every pending dependency's `get...Async()` before its first `await` and assigns `this.#x` before returning. A cached dependency already resolved inside another awaited dependency's subtree is read from its value field and not awaited again. A public `tryGet<Name>(): T | undefined` returns the value field.
- Components are transient dependencies; one with any awaited async `@inject` is resolved asynchronously (`createComponent` returns a `Promise`).
- Diagnostics are `file(line,col): error ZDInn: message`, with 1-based positions in the `.ts` or `.tszor` source.
- Verify with `cargo test`, `bun test`, `bun run test:grammar`, `cargo run -q -- build examples/counter`.

## Review Focus

- An entry module without `@Mount` must build and bundle exactly as today (`main.ts` as entry, no `.zor/main.ts`). Test in Task 8.
- An `@inject` component nested inside another component, or rendered inside a slot fill, must still be built through the application. Test in Task 1.
- A service type that is not exported from its module cannot be imported by generated code; the analyzer reports `error ZDI02: <Type> must be exported to be injected` instead of emitting broken TypeScript. Test in Task 4.
- `zor build --watch` must rebuild when a provider `.ts` file changes, not only `.tszor` files. Test in Task 8.
- Two registrations whose getter names collide (`IDatabase` and `Database`) get `database` and `database1`, not a duplicate member. Test in Task 7.

### Task 4: Analyzer `src/di.ts`

**Files:**
- Create: `src/di.ts`, `tests/di.test.ts`, `tests/fixtures/di/` (`tsconfig.json` like `examples/counter`, `services/data.ts`, `main.ts`, `.zor/Counter.tszor.ts` written by the test from a template)

**Interfaces:**
- Usage: `bun di.ts <projectRoot> <file.ts>... -- <component.tszor.ts>...`. It prints one JSON document to stdout and exits 0, also when the document carries `errors`.
- JSON contract (Rust relies on exactly this):

```ts
type TypeRef = { id: string; text: string; module: string | null; export: string | null };
// id: "<declaring file, project-relative, '/'>#<export name>", or the text for primitives (module/export null).
// module: project-relative path of the declaring file without extension ("services/data"); ".tszor" kept for components ("Counter.tszor").
type Param = { name: string; optional: boolean; promise: boolean; type: TypeRef };  // promise: declared Promise<T>, type is T
type Registration = {
  lifetime: "singleton" | "scoped" | "transient"; service: TypeRef; impl: TypeRef | null; key: string | null;
  factory: { owner: TypeRef; member: string } | null; async: boolean; params: Param[];
  dispose: null | "dispose" | "Symbol.dispose" | "Symbol.asyncDispose"; at: number;  // at: offset of the decorator in file
};
type Provider = { class: TypeRef; file: string; at: number; imports: TypeRef[]; registrations: Registration[];
  mount: null | { component: TypeRef; target: string; at: number } };
type Component = { class: TypeRef; injects: Param[] };   // from the generated constructor
type Facts = { providers: Provider[]; components: Component[]; errors: { file: string; at: number; message: string }[] };
```

### Task 6: Graph resolution and diagnostics

**Files:**
- Create: `src/di/graph.rs`

**Interfaces:**
- Consumes: `Facts` (Task 5).
- Produces:
  - `pub struct Diag { pub file: String, pub at: usize, pub code: &'static str, pub message: String }`
  - `pub enum Source { Own, Imported(usize) }`, where the index points into `provider.imports`.
  - `pub struct Service { pub reg: Registration, pub getter: String, pub source: Source, pub args: Vec<Arg>, pub is_async: bool }`, where `is_async` is the factory's own `async` or any awaited argument's `is_async`, computed to a fixed point
  - `pub enum Arg { Service(usize), Awaited(usize), Promise(usize), Inline(String), Undefined }`. `Awaited` is a `T` parameter on an async service and `Promise` is a `Promise<T>` parameter; both index `Resolved.services`. `Inline` carries the impl text, for parameterless transients.
  - `pub struct Resolved { pub provider: Provider, pub services: Vec<Service>, pub components: Vec<(Component, Vec<Arg>, bool)> }`, where the `bool` marks a component resolved asynchronously
  - `pub fn resolve(facts: &Facts) -> Result<Vec<Resolved>, Vec<Diag>>`
  - `components` is filled only for the `@Mount` provider.
- Rules:
  - Imported providers contribute their registrations as `Source::Imported`; an imported provider is resolved against itself only (self-sufficiency).
  - Parameter lookup: key equal to the parameter name, then service `type.id`.

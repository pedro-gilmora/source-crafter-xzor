# Polish 4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Literal-boundary fixes in template rewriting, `@inherits` bases from packages / re-exports / `.d.ts` with a warning when a base can't be read, per-directory `--watch` on Linux, and string coloring in `@typeparam`.

**Architecture:** All compile-time work stays in Rust with no new crates (`codegen.rs`, `inherit.rs`, `lib.rs`); TypeScript is not consulted at compile time. The watcher change is confined to `src/watch.ts`. The grammar change is one regex in `tszor.tmLanguage.json`.

**Tech Stack:** Rust 2024 (no crates), Bun 1.4 (`bun test`), TextMate grammar tests.

**Spec:** approved in chat on 2026-10-13 (items 1, 2, 4, 5 of the "what's next" list). This plan's Global Constraints carry its decisions.

## Global Constraints

- Zero Rust dependencies; JSON via `src/json.rs`.
- Memory and performance first: no extra passes over sources that don't use the feature; no `@inherits` means no new work.
- Inside a regex literal, string, comment or template text, identifiers are never prefixed with `this.` / `ClassName.`.
- Package resolution: `node_modules/<pkg>` found by walking up from the importing file's directory; `package.json` `types`, then `typings`, then `exports` (string, or the `"types"` condition, searched recursively through nested condition objects, for `"."` or `"./sub"`), then `index.d.ts`; also `node_modules/@types/<pkg>` (`@scope/x` → `@types/scope__x`).
- Not supported (and must produce the warning): tsconfig `paths`, `export =`, bases from expressions (`extends mixin(A)`).
- Warning text, verbatim: `could not read base class '<Name>'; use this.<member> for its members` (`<member>` literal; `<Name>` is the first class in the chain that could not be read).
- Warnings never fail a build.
- Linux `--watch`: never registers a watch inside an ignored directory (`watch.ts`'s `ignored`). Windows/macOS behavior unchanged.

## Review Focus

- A regex right after `return`/`(`/`=` in a template expression containing a member name, e.g. `@onclick="() => ok = /title/.test(name)"` → `/title/` untouched, `this.name` prefixed (Task 1).
- Division in a template expression (`@(a / b / c)`) still prefixes both `a`, `b` and `c` (Task 1).
- `export * from` cycles between two files terminate (Task 2).
- A directory created under the watch root with a file already inside before the watcher attaches still reports that file (Task 4).
- `@typeparam T extends "a//b" | 'c@d'` keeps the whole string colored and no comment scope (Task 5).
